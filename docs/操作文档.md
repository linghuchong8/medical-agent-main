# Windows 与 Linux 操作文档

本文档提供 Windows 与 Linux 两个平台从零开始的完整操作指南：环境准备 → 部署 → 启动 → 日常运维 → 故障排查。

> 更底层的原始部署细节见 `deploy/DEPLOYMENT.md`。

## 一、快速开始（最简路径）

| 场景 | Windows | Linux |
|---|---|---|
| 全新机器一键部署+启动 | 双击项目根目录 `start_dev.bat` | `bash deploy/start_dev.sh` |
| 首次部署 | `deploy\install.bat` | `bash deploy/install.sh` |
| 日常启动 | `deploy\start.bat` | `bash deploy/start.sh` |
| 环境自检 | — | `bash deploy/check_env.sh` |

**部署完成后的验证入口**：
- 健康检查：`http://localhost:8080/health` → `{"status":"ok"}`
- 依赖检查：`http://localhost:8080/health/deps` → 5 项依赖全部 `ok`
- 聊天页面：浏览器打开 `http://localhost:8080/chat`

## 二、环境准备（前置条件）

### 2.1 必须的软件

| 软件 | 版本要求 | Windows 安装 | Linux 安装 |
|---|---|---|---|
| Python | **必须 3.13**（3.12/3.14 依赖会装不上） | https://python.org 下载，勾选 **Add to PATH** | `sudo apt install -y python3.13 python3.13-venv`（Debian/Ubuntu 需 deadsnakes PPA） |
| Docker | 20+ | Docker Desktop for Windows | `curl -fsSL https://get.docker.com | sudo sh` |
| Docker Compose | 随 Docker 或插件 | Docker Desktop 自带 | `sudo apt install -y docker-compose-plugin` |
| Ollama | 0.5+（可选，长期记忆需要） | https://ollama.com/download 安装 | `curl -fsSL https://ollama.com/install.sh | sh` |

### 2.2 Windows 特有注意

1. **Python 安装**：安装器务必勾选 "Add Python to PATH"，否则脚本找不到 `python`。
2. **Docker Desktop**：安装后需启动一次并确认 `docker version` 可运行；WSL2 后端模式推荐。
3. **代理影响**：若本机开了代理软件（如 Clash，默认 127.0.0.1:10809），系统代理可能干扰 Python 调用外部 API。本项目 `start.bat` 已自动清除 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` 环境变量，一般无需手动处理。

### 2.3 Linux 特有注意

1. **权限**：docker 免 sudo 使用：`sudo usermod -aG docker $USER && newgrp docker`。
2. **Ollama systemd**：若用 systemd 管理：`sudo systemctl start ollama`、`sudo systemctl enable ollama`。
3. **脚本权限**：Linux 脚本需执行权限：`chmod +x deploy/*.sh`（或用 `bash deploy/xxx.sh` 方式运行，无需执行位）。
4. **端口放行**：若远程访问 8080，需放行防火墙：`sudo ufw allow 8080`。

## 三、部署（Windows）

### 3.1 方式一：一键部署+启动（推荐）

双击项目根目录 `start_dev.bat`。脚本会自动：
1. 创建 `.venv` 虚拟环境并安装依赖（第一次需几分钟）
2. 若无 `.env` 则复制 `.env.example` 并用记事本打开 → **填写 `DEEPSEEK_API_KEY` 保存 → 回命令行按任意键继续**
3. 启动 Docker Desktop 并等待
4. 启动 7 个基础设施容器（PostgreSQL / Redis / MinIO / etcd / Milvus / Neo4j / attu）
5. 首次自动初始化数据库（alembic 建表 → 导入 PG 数据 → 构建 Neo4j 图谱）
6. 检查 Ollama 并自动拉取 nomic-embed-text
7. 启动应用：`http://localhost:8080`

### 3.2 方式二：分开执行

```
deploy\install.bat      # 首次部署
deploy\start.bat        # 日常启动
```

## 四、部署（Linux）

### 4.1 方式一：一键部署+启动（推荐）

```bash
cd /path/to/tiangong-agent-main
bash deploy/start_dev.sh
```

脚本会自动：创建 `.venv` 装依赖（`requirements-linux.txt`）→ 生成 `.env`（提示 `vi .env` 填 `DEEPSEEK_API_KEY` 后回车）→ 启动 Docker 与容器 → 初始化数据库 → 检查 Ollama → 启动应用。

### 4.2 方式二：先自检再部署

```bash
bash deploy/check_env.sh        # 环境自检（绿=OK，黄=警告，红=失败，退出码=问题数）
bash deploy/install.sh          # 首次部署
bash deploy/start.sh            # 日常启动
```

## 五、环境变量配置（.env）

### 5.1 生成与编辑

- 首次部署脚本会自动从 `.env.example` 复制生成 `.env`。
- Windows 编辑：`notepad .env`；Linux 编辑：`vi .env`。
- **改动 `.env` 后必须重启应用才生效**。

### 5.2 配置项总表

| 配置项 | 默认值 | 说明 | 是否必填 |
|---|---|---|---|
| `APP_NAME` | `tiangong-agent` | 应用名 | 否 |
| `APP_ENV` | `dev` | 运行环境 | 否 |
| `APP_DEBUG` | `true` | 调试模式（打印 SQL） | 否 |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | localhost / 5432 / medical / medical123 / medical_db | PostgreSQL 连接 | 默认可用 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` / `REDIS_DB` | localhost / 6379 / 空 / 0 | Redis 连接 | 默认可用 |
| `MINIO_ENDPOINT` / `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` / `MINIO_BUCKET` / `MINIO_SECURE` | localhost:9000 / minioadmin / minioadmin / knowledge-docs / false | MinIO 连接 | 默认可用 |
| `MILVUS_HOST` / `MILVUS_PORT` | localhost / 19530 | Milvus 连接 | 默认可用 |
| `NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD` | bolt://localhost:7687 / neo4j / medical123 | Neo4j 连接 | 默认可用 |
| `DEEPSEEK_API_KEY` | 空 | **DeepSeek 对话密钥，不填则对话报 401** | **✅ 必填** |
| `DEEPSEEK_MODEL` | deepseek-chat | 模型名（代码当前硬编码 `deepseek-v4-flash`，此配置未生效） | 否 |
| `DASHSCOPE_API_KEY` / `BASE_URL_CHAT` / `CHAT_MODEL` | — | 阿里 DashScope 历史遗留配置（已弃用） | 否 |
| `LOG_LEVEL` / `LOG_DIR` | DEBUG / logs | 日志级别与目录 | 否 |

> ⚠️ 注意：即使填了 `DEEPSEEK_MODEL`、`EMBEDDING_MODEL`，代码中聊天模型与向量模型是硬编码的（deepseek-v4-flash + Ollama nomic-embed-text），修改 .env 不会改变实际使用的模型。

## 六、日常运维

### 6.1 启动 / 停止

| 操作 | Windows | Linux |
|---|---|---|
| 启动 | `deploy\start.bat` | `bash deploy/start.sh` |
| 停止应用 | 命令行 Ctrl+C | 命令行 Ctrl+C |
| 停止全部容器 | `docker compose down` | `docker compose down` |
| 停止并清数据卷 | `docker compose down -v`（会清空数据库！） | 同左 |

### 6.2 查看状态

| 操作 | 命令 |
|---|---|
| 容器状态 | `docker compose ps` |
| 容器日志 | `docker compose logs -f <服务名>`（如 postgres/milvus/neo4j） |
| 应用日志 | Windows/Linux：`logs/` 目录下 `YYYY-MM-DD.log`（每日轮转，保留 30 天） |
| 健康检查 | `curl http://localhost:8080/health` |
| 依赖检查 | `curl http://localhost:8080/health/deps` |

### 6.3 应用升级（改代码后）

```
Windows:
    deploy\start.bat            # 重新启动即加载新代码
Linux:
    bash deploy/start.sh
```

> 若启动了新的基础设施版本，运行 `docker compose pull && docker compose up -d`。

### 6.4 运行自动化测试

```
Windows: .venv\Scripts\python.exe -m pytest test -v
Linux:   .venv/bin/python -m pytest test -v
```
预期结果：**3 passed**（需 DEEPSEEK_API_KEY 与全部基础设施运行）。

### 6.5 数据管理

- **手动重建数据库**：删除 `.deployed` 文件 → 运行 `deploy\install.bat`（Linux: `bash deploy/install.sh`）→ 会重新初始化。
- **手动跑迁移**：`.venv\Scripts\python.exe -m alembic upgrade head`。
- **长期记忆向量维度冲突修复**（旧集合为 1024 维）：删除 Milvus 集合 `agent_long_term_memory` 后重启应用自动重建为 768 维：
  ```
  docker compose exec milvus python -c "from pymilvus import utility; utility.drop_collection('agent_long_term_memory')"
  ```

## 七、故障排查

### 7.1 通用排查步骤

1. 看健康检查：`http://localhost:8080/health/deps`，判断哪个依赖失败。
2. 看容器状态：`docker compose ps`，确认没有 starting/unhealthy。
3. 看应用日志：`logs/` 目录最新日志文件。

### 7.2 常见问题对照表

| 现象 | 原因 / 解决 |
|---|---|
| `GET /` 返回 404 | 正常。根路径无路由，请访问 `/chat` 或 `/health` |
| 页面打不开 localhost:8080 | 应用未启动，运行 `start.bat`/`start.sh`；或端口被占用 |
| 对话报 500 Connection error | 网络/代理问题。用 start 脚本启动（会自动清代理变量）；确认能访问 api.deepseek.com |
| 对话报 401 invalid token | `.env` 中 `DEEPSEEK_API_KEY` 错误或残留旧环境变量覆盖。清除 `DEEPSEEK_API_KEY` 环境变量后重启 |
| 对话报 400 tool_calls / tool messages | Redis checkpoint 状态损坏。系统已自动重置重试；仍失败则清 Redis 或删除该会话 |
| 对话超时（504） | 模型响应超过 180 秒。多为网络慢/模型排队，稍后重试 |
| 长期记忆不可用 | Ollama 未运行或未拉模型：`ollama pull nomic-embed-text`；确认 `http://127.0.0.1:11434` 可访问 |
| Milvus 向量检索报错 | Milvus 容器未就绪，或集合维度不匹配（1024 vs 768），按 6.5 删除重建 |
| 部署卡在"等待 Docker" | Docker Desktop/服务未启动，手动启动后重跑 |
| 数据库初始化失败 | `docker compose ps` 确认容器健康；删除 `.deployed` 重跑 install |
| 改了代码不生效 | 重启应用（start 脚本）；uvicorn 非 reload 模式需重启 |
| Linux 端口被占 | `ss -ltn` 查看，项目自身服务占用属正常 |
| 依赖安装失败 | 确认 Python 版本为 **3.13**；Windows 用 `requirements.txt`，Linux 用 `requirements-linux.txt` |

### 7.3 常见问题深入：DeepSeek 连接失败

本项目曾出现过：应用进程继承了系统代理（127.0.0.1:10809）导致调用 DeepSeek 报 `openai.APIConnectionError: Connection error`。

**排查命令**：
```powershell
# PowerShell
$r = Invoke-WebRequest -Uri 'https://api.deepseek.com/v1/models' -Headers @{Authorization="Bearer <你的KEY>"} -UseBasicParsing -TimeoutSec 20
$r.StatusCode   # 200 = 网络通、Key 有效
```

**解决**：确认 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` 环境变量为空后重启应用（`start.bat`/`start.sh` 已自动处理）。
