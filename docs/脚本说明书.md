# 脚本说明书

本文档详细说明项目全部脚本的用途、参数、执行流程与退出行为。分两大类：

1. **部署/启动脚本**（`deploy/` 目录）
2. **数据初始化脚本**（`scripts/` 目录）

---

## 一、部署/启动脚本（deploy/）

### 1.1 脚本总览

| 脚本 | 平台 | 作用 | 一次性/日常 |
|---|---|---|---|
| `install.bat` | Windows | 首次部署（7 步） | 一次性 |
| `install.sh` | Linux | 首次部署（7 步） | 一次性 |

### 1.2 `install.bat` / `install.sh` — 首次部署脚本

**用途**：全新机器上完成全部初始化。**已部署过（存在 `.deployed` 标记）会跳过数据库初始化。**

**执行流程（7 步）**：

| 步骤 | 内容 | 失败处理 |
|---|---|---|
| 1 | 定位 Python（Windows 先试 `python`，再试 `py -3.13`；Linux 要求 `python3` ≥ 3.13） | 找不到 → 提示安装 Python 3.13，退出码 1 |
| 2 | 无 `.venv` 则创建虚拟环境并安装依赖（Windows 用 `requirements.txt`，Linux 用 `requirements-linux.txt`） | 装依赖失败 → 提示检查网络，退出码 1 |
| 3 | 无 `.env` 则复制 `.env.example` 并打开编辑（Windows 用 notepad；Linux 提示 `vi .env` 后回车继续） | — |
| 4 | 检查 Docker，未启动则自动启动（Windows 启动 Docker Desktop，Linux `systemctl start docker`），最多等 5 分钟 | 超时 → 退出码 1 |
| 5 | `docker compose up -d` 启动 7 个基础设施容器，等待全部 healthy（最多 5 分钟） | 失败 → 提示 `docker compose ps`，退出码 1 |
| 6 | **仅当 `.deployed` 不存在时**执行：`alembic upgrade head` 建表 → `scripts/init_postgres.py` 导入 PostgreSQL 数据（2-3 分钟）→ `scripts/init_neo4j.py` 构建知识图谱（5-10 分钟）→ 创建 `.deployed` 空文件 | 任一步失败 → 对应中文错误提示，退出码 1 |
| 7 | 检查 Ollama：未运行则警告"长期记忆不可用，对话仍可工作"；已运行但缺 `nomic-embed-text` 模型则自动 `ollama pull nomic-embed-text`（约 274MB） | 仅警告，不阻断 |

**关键机制 —— `.deployed` 标记文件**：
- 文件存在 = 数据库已初始化，`install` 的步骤 6 会跳过，避免重复导入。
- 删除该文件后重新运行 install 会重新初始化数据库。

**退出码**：成功 0；任何错误 1。

**重要注意（Windows）**：
- 步骤 3 中，`copy .env.example .env` 后会用 `notepad .env` 打开，**保存后需在命令行窗口按任意键继续**。

### 1.3 `start.bat` / `start.sh` — 日常启动脚本

**用途**：日常启动服务。

**执行流程（3 步）**：

| 步骤 | 内容 |
|---|---|
| 0 | 若 `.deployed` 不存在，自动调用 install 完成部署 |
| 1 | 检查 Docker，未启动则自动启动并等待（Windows Docker Desktop / Linux systemctl），最多 5 分钟 |
| 2 | `docker compose up -d` 确保容器运行 |
| 3 | **清空残留环境变量**（`DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` / `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`）后，启动 `uvicorn src.main:app --host 0.0.0.0 --port 8080` |

**为什么步骤 3 要清环境变量？**
- 保证 `.env` 中的 API Key 生效，避免被 shell 中残留的旧环境变量覆盖（曾导致调用 DeepSeek 报 401 / Connection error）。
- 清除代理变量可避免本机系统代理（如 127.0.0.1:10809）拦截外呼。

**注意**：
- Windows 版本为前台运行，`Ctrl+C` 停止，结束后 `pause`。
- Linux 版本用 `exec` 替换为 uvicorn 进程，`Ctrl+C` 停止。
- 应用默认端口 **8080**。

### 1.4 `start_dev.bat` / `start_dev.sh` — 一键部署 + 启动

**用途**：全新机器一条命令完成部署并启动；已部署过的机器直接启动。

```
Windows: 双击 start_dev.bat 或 deploy\start_dev.bat
Linux:   bash deploy/start_dev.sh
```

**执行流程**：依次调用 `install.sh/bat` → `start.sh/bat`。任一环节失败即中止。

### 1.5 `check_env.sh` — Linux 环境自检

**用途**：部署前检查必备软件是否齐全，缺失时给出安装命令。

**执行**：`bash deploy/check_env.sh`

**检查项**：

| 检查项 | 通过标准 | 失败提示的安装命令 |
|---|---|---|
| 系统版本 | 读取 /etc/os-release | — |
| python3 | ≥ 3.13 | `sudo apt install -y python3.13 python3.13-venv`（deadsnakes PPA） |
| venv 模块 | `python3 -m venv --help` 可用 | `sudo apt install -y python3.13-venv` |
| docker | 已安装 | `curl -fsSL https://get.docker.com | sudo sh` |
| docker compose | 插件可用 | `sudo apt install -y docker-compose-plugin` |
| Docker 引擎 | `docker info` 成功 | `sudo systemctl start docker`；免 sudo：`sudo usermod -aG docker $USER && newgrp docker` |
| ollama | 已安装 | `curl -fsSL https://ollama.com/install.sh | sh` |
| Ollama 服务 | `127.0.0.1:11434` 可访问 | `sudo systemctl start ollama` |
| embedding 模型 | `ollama list` 含 nomic-embed-text | `ollama pull nomic-embed-text` |
| 关键端口 | 8080 / 5432 / 6379 / 19530 / 7687 / 11434 | 已占用会警告（项目自身服务占用属正常） |

**输出**：绿 `[OK]` / 黄 `[!!]`（警告）/ 红 `[X]`（失败）三色输出。

**退出码**：等于发现的问题数（0 = 全部通过）。

## 二、数据初始化脚本（scripts/）

### 2.1 `scripts/init_postgres.py` — PostgreSQL 数据导入

**用途**：从 `data/raw/medical.json`（JSONL，8807 条疾病）导入 PostgreSQL。

**前置条件**：已执行 `alembic upgrade head` 建表；PostgreSQL 容器运行中。

**幂等性**：可重复运行，不会产生重复数据（科室/症状用 `ON CONFLICT DO NOTHING`，药品先查后插）。

**导入流程（4 步）**：

| 步骤 | 内容 |
|---|---|
| 1 | 收集 `cure_department` / `department` 去重 → 导入 `departments` 表 |
| 2 | 收集 `symptom` 去重 → 导入 `symptoms` 表 |
| 3 | `common_drug` + `recommand_drug` 去重 → 导入 `drugs` 表 |
| 4 | 每条疾病记录 → `diseases` 表（取第一个科室为 department_id，`cure_way` 列表转逗号分隔字符串）；同时填充 `disease_symptoms`、`disease_drugs`（relation_type 区分 common/recommend） |

**预期数据量**：科室 54、症状 5998、药品 3828、疾病 8807、疾病-症状关联 54707、疾病-药品关联 74119。

**运行**：
```
Windows: .venv\Scripts\python.exe scripts/init_postgres.py
Linux:   .venv/bin/python scripts/init_postgres.py
```

### 2.2 `scripts/init_neo4j.py` — Neo4j 知识图谱构建

**用途**：从同一 medical.json 构建 Neo4j 医学知识图谱。

**前置条件**：Neo4j 容器运行中且已加载 APOC 插件（docker-compose 中已配置 `NEO4J_PLUGINS=["apoc"]`）。

**执行流程（10 步）**：

| 步骤 | 内容 |
|---|---|
| 1 | 连接 Neo4j |
| 2 | 分批 `DETACH DELETE` 清空旧数据（生产慎用） |
| 3 | 为 7 类节点（Disease/Symptom/Drug/Department/Check/Food/Producer）创建 `name IS UNIQUE` 唯一性约束 |
| 4 | 加载 JSON 数据 |
| 5 | 第一轮遍历收集 7 类实体去重集合 |
| 6 | 第二轮 `UNWIND + MERGE` 批量建节点（每批 500，幂等） |
| 7 | 第三轮收集关系对：8 类关系（HAS_SYMPTOM / BELONGS_TO / COMMON_DRUG / RECOMMEND_DRUG / NEED_CHECK / DO_EAT / NO_EAT / ACOMPANY_WITH） |
| 8 | `UNWIND + MATCH + MERGE` 批量写关系 |
| 9 | 为 Disease 节点 SET 属性（description/cause/prevent 等，只写非空值） |
| 10 | 输出统计 + 给出验证 Cypher |

**预期数据量**：Disease 8807 / Symptom 5998 / Drug 3828 / Food 4746 / Check 3353 / Department 54；关系约 25.9 万条。

**运行**：
```
Windows: .venv\Scripts\python.exe scripts/init_neo4j.py
Linux:   .venv/bin/python scripts/init_neo4j.py
```

## 五、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 脚本报"未找到 Python 3.13" | 安装 Python 3.13 并加入 PATH；Linux 可用 deadsnakes PPA |
| 部署卡在等待 Docker | Docker Desktop / docker 服务未启动，手动打开后重跑 |
| 数据库初始化失败 | 先确认容器健康（`docker compose ps`），必要时删除 `.deployed` 重跑 install |
| `notepad .env` 后脚本无反应 | 保存 .env 后需在命令行窗口按任意键 |
| 对话报 Connection error / 401 | 清空 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY 后重启服务（start 脚本已自动处理）；确认 .env 中 DEEPSEEK_API_KEY 正确 |
| 长期记忆失效 | 确认 Ollama 运行且已 `ollama pull nomic-embed-text`；Milvus 集合维度若为 1024 需删除重建（见 DEPLOYMENT.md） |
