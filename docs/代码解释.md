# 代码解释

本文件详细解释《医疗-智能体》项目的代码结构、核心实现与数据流。

## 一、项目概述

**项目名称**：医疗-智能体（tiangong-agent）

**技术栈**：
- Python 3.13（严格版本要求）
- FastAPI（Web 框架，异步）
- LangGraph / LangChain（Agent 编排）
- SQLAlchemy 2.0（异步 ORM）+ Alembic（数据库迁移）
- Redis Stack（短期记忆 checkpoint，需 RediSearch/RedisJSON）
- Milvus（长期记忆向量库）
- MinIO（对象存储）
- Neo4j（医学知识图谱）
- Ollama（本地向量化模型 nomic-embed-text）
- DeepSeek API（对话/推理大模型，外部依赖）

## 三、核心文件逐文件解释

### 3.1 `src/main.py` — FastAPI 应用入口

**职责**：组装应用、注册中间件/路由/异常处理、管理生命周期、提供健康检查。

| 函数 | 签名 | 用途 |
|---|---|---|
| `lifespan(app)` | `async @asynccontextmanager` | 启停钩子。启动时依次：`setup_logger()` → `ensure_bucket_exists()`（MinIO 建桶）→ `check_milvus_health()` → `check_neo4j_health()`，各自 try/except 容错，失败仅告警不阻断启动。关闭时：`close_neo4j_driver()` → `close_milvus_client()` → `engine.dispose()` |
| `create_app()` | `() -> FastAPI` | 创建应用，注册 `LoggingMiddleware`、`CORSMiddleware`（放行 localhost:3000 / 5173）、异常处理器、两个路由（chat_router、chat_page_router） |
| `GET /health` | — | 返回 `{"status": "ok"}` |
| `GET /health/deps` | — | 逐项探测 5 个依赖（PostgreSQL/Redis/MinIO/Milvus/Neo4j），全通返回 ok，任一失败返回 degraded |

### 3.2 `src/agents/supervisor_agent.py` — 监督 Agent（系统核心）

**职责**：构建并缓存 LangGraph 监督 Agent，提供对话入口。

| 函数 | 用途 |
|---|---|
| `_get_embedding_model()` | 返回 Ollama 本地向量化模型 `nomic-embed-text`，`keep_alive=-1` 常驻内存 |
| `_warmup_embedding(model)` | 预热模型：Ollama 首次加载 embed 会 503，最多重试 6 次，指数退避（2^n 秒，上限 20s） |
| `create_supervisor_agent()` | 组装 Agent：① checkpointer 专用 Redis 客户端 + `AsyncRedisSaver` + `asetup()` 建 RediSearch 索引 → ② Milvus 连接 + Ollama embedding + `MilvusStore(dims=768)` → ③ 工具 `[save_memory, search_memory]` → ④ `create_agent(model="deepseek-v4-flash", ...)` |
| `get_supervisor_agent()` | 模块级单例，`asyncio.Lock` 双重检查防止并发重复创建 |
| `chat_endpoint(user_id, session_id, message)` | 调用 Agent，`thread_id=f"{user_id}:{session_id}"` 作短期记忆隔离键，返回最后一条消息内容 |

**记忆体系**：
- **短期记忆**：LangGraph checkpointer → Redis（`AsyncRedisSaver`），按 `thread_id = user_id:session_id` 隔离会话。
- **长期记忆**：LangGraph `store` 参数 → `MilvusStore`，按用户跨会话共享。

**注意**：`model="deepseek-v4-flash"` 与 Ollama 地址/模型名均为硬编码，未走 `.env` 配置。

### 3.3 `src/agents/store_tools.py` — 长期记忆工具

| 函数 | 用途 |
|---|---|
| `get_user_id(runtime)` | 从 `runtime.config.configurable.thread_id` 中 `split(":")[0]` 提取 user_id |
| `save_memory(content, runtime)` | 保存记忆到 `namespace=("users", user_id, "memories")`，key=`memory_{时间戳}`，经 `runtime.store.aput()` 写入 Milvus |
| `search_memory(query, runtime)` | 语义检索 `runtime.store.asearch(namespace, query, limit=5)`，返回相关记忆或"没有找到相关记忆" |

### 3.4 `src/infra/database.py` — PostgreSQL 异步访问

- `engine`：`create_async_engine(settings.DATABASE_URL, pool_size=10, max_overflow=20, pool_timeout=30, pool_recycle=300, pool_pre_ping=True)`。
- `get_db()`：FastAPI 依赖注入，yield 后自动 commit，异常 rollback。

### 3.5 `src/infra/redis_cache.py` — Redis 双连接池

| 对象 | 用途 |
|---|---|
| `redis_pool` / `_redis_client` | 业务连接池（`decode_responses=True` UTF-8 模式），模块级单例 |
| `get_redis_client()` | FastAPI Depends 注入用 |
| `_checkpointer_pool` / `_checkpointer_client` | checkpoint 专用池（`decode_responses=False` **bytes 模式**，RedisSaver 硬性要求） |
| `get_checkpointer_redis()` | 返回 bytes 模式客户端 |

两个池独立，互不干扰。

### 3.6 `src/infra/milvus_store.py` — 长期记忆核心存储

**职责**：实现 LangGraph `BaseStore` 接口，将长期记忆存入 Milvus，支持语义相似度检索。

**Collection**：`agent_long_term_memory`，字段 `id / namespace / key / value_json / embedding(FLOAT_VECTOR, 768) / created_at`，索引 `COSINE + IVF_FLAT(nlist=128)`。

| 函数 | 用途 |
|---|---|
| `_ensure_collection(alias, dims)` | 集合不存在则创建、建索引、load |
| `batch(ops)` | 同步批量操作，用 `asyncio.run()`（LangGraph sync tool 在 thread pool 执行，线程无 event loop） |
| `_aput(namespace, key, value)` | Upsert：value 为 None 删除，否则 JSON 化 → 向量化 → 删旧插新 → flush |
| `_asearch(namespace_prefix, query, limit)` | COSINE 向量检索（nprobe=16），无 query 时按前缀列举 |

### 3.7 `src/modules/chat.py` — 聊天 API 模块

- `router = APIRouter(prefix="/api/v1")`，`page_router = APIRouter()`。
- `CHAT_TIMEOUT_SECONDS = 180`：模型响应最长等待，超时返回 504。

| 路由 | 用途 |
|---|---|
| `POST /api/v1/chat` | 主对话接口。`asyncio.wait_for(chat_endpoint(...), timeout=180)`。**自愈逻辑**：异常含 `"tool_calls"` 与 `"tool messages"`（Redis checkpoint 状态损坏）时自动 `_reset_thread_checkpoints()` 清该会话重试一次 |
| `GET /chat` | 返回内置 HTML 聊天页（单文件页面，localStorage 持久化 tg_uid/tg_sid，200s 前端超时） |

### 3.8 `src/modules/medical/model.py` — 医疗数据 ORM 模型（8 张表）

| 表 | 说明 | 关键字段 |
|---|---|---|
| `departments` | 科室 | name(唯一), description |
| `diseases` | 疾病 | name(唯一), department_id(FK), description, cause, prevent, cure_way, cured_prob, cost_money 等 |
| `symptoms` | 症状 | name(唯一) |
| `disease_symptoms` | 疾病-症状多对多 | disease_id(FK), symptom_id(FK) |
| `drugs` | 药品 | name, category, is_otc, stock_quantity, price, expire_date |
| `drug_details` | 药品详情(1:1) | drug_id(FK 唯一), indication, usage_dosage, adverse_reaction, contraindication, precaution, interaction, storage, full_instruction |
| `disease_drugs` | 疾病-药品多对多 | disease_id, drug_id, relation_type(common/recommend) |
| `patients` | 患者档案 | name, gender, age, allergy_history, medical_history, blood_type |
| `consultations` | 问诊记录 | patient_id(FK), chief_complaint, diagnosis, prescription, urgency_level, session_id, milvus_doc_id |

### 3.9 `src/core/config.py` — 配置中心

`Settings(BaseSettings)` 从 `.env` 读取，`get_settings()` 用 `@lru_cache` 单例。`DATABASE_URL` 为派生属性：
```
postgresql+asyncpg://{DB_USER}:{DB_PASSWORD}@{DB_HOST}:{DB_PORT}/{DB_NAME}
```

### 3.10 其它支撑模块

- `src/core/logger.py`：loguru，控制台彩色 + `logs/{YYYY-MM-DD}.log`，每日 00:00 轮转、保留 30 天、gz 压缩。
- `src/core/exceptions.py`：`BizException(code, message)` + 注册异常处理器（全局异常返回 500 并记录堆栈）。
- `src/core/base_model.py`：`Base` + `TimestampMixin` + `BaseModel`（BigInteger 自增 id）。
- `src/core/base_repository.py`：`BaseRepository`，`get_page(offset, limit, keyword, search_fields)` 多字段 OR 模糊搜索。
- `src/middlewares/logging.py`：记录 `--> METHOD path` 和 `<-- METHOD path status=X XXms`。
- `src/utils/jwt_utils.py`：HS256 JWT，30 分钟过期，`OAuth2PasswordBearer(tokenUrl="/api/v1/auth/login")`。
- `src/utils/password_utils.py`：bcrypt 哈希/校验。

> ⚠️ 注意：`src/core/deps.py` 中 `from src.modules.user.model import User` 引用的模块**不存在**（仅剩 `src/modules/medical/`），一旦被导入即报 ImportError。当前 main.py 未导入该文件，故不影响运行，属遗留代码。

## 四、对话主链路数据流

```
用户（浏览器 /chat 页面 或 HTTP POST /api/v1/chat）
  │  body: {user_id, session_id, message}
  ▼
LoggingMiddleware ── 记录耗时
  ▼
POST /api/v1/chat (src/modules/chat.py)
  │  asyncio.wait_for(chat_endpoint(...), timeout=180)
  ▼
chat_endpoint(user_id, session_id, message)  (src/agents/supervisor_agent.py)
  │  取单例 Agent（首次创建：加锁、构建）
  │  config.thread_id = "user_id:session_id"
  ▼
LangGraph Agent (create_agent, model=deepseek-v4-flash)
  │
  ├── 1) 短期记忆加载：checkpointer=AsyncRedisSaver
  │     → Redis Stack（RediSearch checkpoint/checkpoint_write 索引）
  │     → 恢复该 thread_id 的历史消息（会话上下文）
  │
  ├── 2) 请求 DeepSeek API 生成回复
  │     └── 模型按需调用工具：
  │         ├─ save_memory(content)  → 长期记忆写入
  │         │     → runtime.store.aput(namespace=("users",uid,"memories"))
  │         │     → MilvusStore._aput：value JSON 化
  │         │       → Ollama nomic-embed-text 向量化 (768维, 6次重试退避)
  │         │       → Milvus 集合 agent_long_term_memory 插入 + flush
  │         │
  │         └─ search_memory(query)  → 长期记忆检索
  │               → runtime.store.asearch(namespace, query, limit=5)
  │               → MilvusStore._asearch：query 向量化
  │                 → Milvus COSINE 向量检索 (nprobe=16, namespace 前缀过滤)
  │                 → 返回相关记忆文本给模型
  │
  ├── 3) 会话状态写回 Redis checkpoint（短期记忆持久化）
  │
  └── 返回 result["messages"][-1].content
  ▼
ChatResponse {user_id, session_id, reply}
```

## 五、记忆体系

| 记忆类型 | 存储 | 隔离粒度 | 实现 | 生命周期 |
|---|---|---|---|---|
| 短期记忆 | Redis Stack | `thread_id = user_id:session_id` | `AsyncRedisSaver` (LangGraph checkpointer) | 会话级 |
| 长期记忆 | Milvus | `namespace = users/{user_id}/memories` | `MilvusStore` (自定义 BaseStore) + Ollama 向量化 | 跨会话永久，按用户隔离 |

## 六、启动流程

```
uvicorn src.main:app
  → lifespan:
      setup_logger()
      ensure_bucket_exists()     → MinIO 建桶 knowledge-docs
      check_milvus_health()      → Milvus 连接
      check_neo4j_health()       → Neo4j 连接
  → 首轮对话时（懒加载）:
      get_supervisor_agent() 加锁创建：
        AsyncRedisSaver.asetup()      → 建 RediSearch 索引
        OllamaEmbeddings + 预热         → nomic-embed-text 常驻
        MilvusStore()                 → 建 agent_long_term_memory 集合+索引
        create_agent(...)             → 组装 LangGraph Agent
```

## 七、组件依赖矩阵

| 组件 | 端口 | 被谁使用 | 缺失影响 |
|---|---|---|---|
| PostgreSQL 17.9 | 5432 | SQLAlchemy 异步引擎、Alembic、init_postgres.py | 结构化查询不可用 |
| Redis Stack 7.4 | 6379 / 8001 | AsyncRedisSaver 短期记忆（**必须 Redis Stack**，标准 redis 缺 RedisJSON） | 会话短期记忆不可用，对话报 400 tool_calls 状态损坏 |
| Milvus 2.6.13 | 19530 / 9091 | MilvusStore 长期记忆 | 长期记忆不可用 |
| MinIO | 9000 / 9001 | 文件上传 + Milvus 底层向量文件存储 | 文件功能不可用，**Milvus 也会挂** |
| etcd | 无映射 | Milvus 元数据 | Milvus 无法启动 |
| Neo4j 5.20 | 7474 / 7687 | init_neo4j.py 构建图谱 | 图谱功能不可用 |
| Ollama | 11434 | OllamaEmbeddings（nomic-embed-text） | 长期记忆不可用，对话仍可工作 |
| DeepSeek API | 外部 | Agent 聊天/推理模型 | 无法对话 |

**容器依赖链**：`milvus` depends_on `etcd` + `minio`；`attu` depends_on `milvus`；全部在 `tiangong-net` 网络。

## 八、已知注意点

1. **悬空导入**：`src/core/deps.py` 引用不存在的 `src.modules.user.model`。
