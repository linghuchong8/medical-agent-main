# 医疗智能体 —— 克隆部署教程

> 本文档面向**从 GitHub 克隆本仓库到部署成功跑通**的完整流程。
> 仓库地址：https://github.com/linghuchong8/medical-agent-main
> 覆盖平台：Windows 与 Linux（Ubuntu/Debian 为主）。
> 版本要求：**Python 3.13**（必须，3.12/3.14 会导致依赖安装失败）。

---

## 一、架构总览

```
浏览器 / HTTP 客户端
        │  :8080
        ▼
  FastAPI 应用 (uvicorn)  ──┬── PostgreSQL   :5432   结构化数据（药品/疾病/患者）
   src/main.py              ├── Redis        :6379   会话短期记忆（LangGraph checkpoint）
        │                   ├── Milvus       :19530  长期记忆向量库（Agent 记忆）
        │                   ├── MinIO       :9000   文件存储（知识文档）
        │                   ├── Neo4j       :7687   医学知识图谱
        │                   └── attu        :3000   Milvus 可视化客户端（可选）
        │
        ├── Ollama :11434  ── nomic-embed-text   本地向量化（长期记忆）
        └── DeepSeek API（外部）── deepseek-v4-flash  聊天/推理模型
```

| 组件 | 必需性 | 缺失时影响 |
|---|---|---|
| PostgreSQL + Redis + MinIO + Milvus + Neo4j（Docker 一组起） | 必需 | `/health/deps` 降级，相关功能不可用 |
| Ollama + nomic-embed-text | 必需 | 长期记忆（保存/检索病史、过敏史）不可用 |
| DeepSeek API Key | 必需 | Agent 无法对话 |
| attu | 可选 | 仅 Milvus 可视化，不影响功能 |

> **重要**：本仓库**自带 docker 数据卷**（PostgreSQL 医学数据、Neo4j 图谱、MinIO 文件、etcd 元数据、Redis 数据，约 900MB）和 `.deployed` 标记，因此克隆后**基础数据已就位，默认跳过数据库初始化**，部署时间大大缩短。`.env`（含 API 密钥）**不在仓库中**，需自行创建。

## 二、前置条件清单

| 软件 | 最低版本 | Windows 检测 | Linux 检测 |
|---|---|---|---|
| Python | **3.13.x** | `python --version` | `python3 --version` |
| Docker | 20+ | `docker version` | `docker --version` |
| Docker Compose | 2.x | `docker compose version` | `docker compose version` |
| Ollama | 0.5+ | `ollama --version` | `ollama --version` |
| Git | - | `git --version` | `git --version` |

> ⚠️ 部署前建议清空环境变量 `DEEPSEEK_API_KEY`，否则会覆盖 `.env` 里的新 key，导致对话报 401：
> - Windows：`set DEEPSEEK_API_KEY=`
> - Linux：`unset DEEPSEEK_API_KEY`

### 安装指引

- **Python 3.13**：https://www.python.org/downloads/ （Windows 安装时**务必勾选 "Add Python to PATH"**）；Linux 可用 `sudo add-apt-repository ppa:deadsnakes/ppa -y && sudo apt install -y python3.13 python3.13-venv`。
- **Docker Desktop（Windows）**：https://www.docker.com/products/docker-desktop/ ，首次需启用 WSL2；**Docker Engine（Linux）**：`curl -fsSL https://get.docker.com | sudo sh`，再 `sudo usermod -aG docker $USER`。
- **Ollama**：Windows https://ollama.com/download/windows ；Linux `curl -fsSL https://ollama.com/install.sh | sh`。
- 装完 Ollama 后拉取 embedding 模型（约 274MB）：

```sh
ollama pull nomic-embed-text
```

## 三、快速上手（一键脚本，推荐）

装好上面的软件后，只需 3 步即可跑通：

### 步骤 1：克隆仓库

```sh
git clone https://github.com/linghuchong8/medical-agent-main.git
cd medical-agent-main
```

### 步骤 2：创建并配置 .env

```sh
# Windows
copy .env.example .env
notepad .env          # 至少把 DEEPSEEK_API_KEY=sk-xxxx 填上，保存

# Linux
cp .env.example .env
vi .env               # 至少把 DEEPSEEK_API_KEY=sk-xxxx 填上，保存
```

### 步骤 3：一键部署 + 启动

- **Windows**：双击根目录的 `start_dev.bat`（首次会自动装依赖、起 Docker、跳过已就位的数据初始化，然后启动服务）
- **Linux**：
  ```sh
  chmod +x deploy/*.sh
  ./deploy/start_dev.sh
  ```

看到日志 `Application startup complete` 即成功。浏览器打开 **http://localhost:8080/chat** 开始对话。

> 一键脚本 = 部署（`install.bat/.sh`，仅首次，用 `.deployed` 标记控制跳过）+ 启动（`start.bat/.sh`，日常）。日常只需跑启动脚本。

## 四、手动逐步部署

> 与一键脚本等效，每步手动执行，便于理解与排查。以下命令在项目根目录执行。

### ① 创建虚拟环境并安装依赖

```sh
# Windows
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt          # 约 3-5 分钟，237 个包

# Linux（⚠️ 用 requirements-linux.txt，已剔除 pywin32 等 Windows 专属包）
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements-linux.txt
```

✔ 预期：最后出现 `Successfully installed ...`
✘ 失败：见「六、常见问题排查」第 2 条（网络/镜像）。

### ② 配置环境变量

```sh
# Windows
copy .env.example .env
# Linux
cp .env.example .env
```

用编辑器打开 `.env`，重点字段：

| 字段 | 含义 | 是否需改 |
|---|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek 对话密钥 | ✅ **必须填**，`sk-` 开头 |
| `DEEPSEEK_MODEL` | 模型名 | 否（写死勿改） |
| `DB_*` / `REDIS_*` / `MINIO_*` / `MILVUS_*` / `NEO4J_*` | 各组件连接 | 否（默认与 docker-compose 一致） |
| `DASHSCOPE_API_KEY` | 阿里 DashScope（已不用） | 留空即可 |

### ③ 启动基础设施（Docker）

```sh
docker compose up -d
docker compose ps
```

✔ 预期 7 个容器全部 `Up (healthy)`（milvus 最慢，启动约 1-2 分钟）：

```
NAMES                    STATUS
tiangong-postgres        Up 1 minute (healthy)
tiangong-redis           Up 1 minute (healthy)
tiangong-minio           Up 1 minute (healthy)
tiangong-neo4j           Up 1 minute (healthy)
tiangong-milvus          Up 1 minute (healthy)
tiangong-milvus-etcd     Up 1 minute
tiangong-attu            Up 1 minute
```

✘ 失败：端口被占用或镜像拉取慢，见「六、常见问题排查」第 1、3 条。

### ④ 数据库初始化（一般自动跳过）

本仓库已自带数据卷和 `.deployed` 标记，**克隆后无需初始化**。仅当需要**从零重建**时才执行（见「六、常见问题排查」第 7 条）。

### ⑤ 启动应用

```sh
# Windows
.venv\Scripts\python.exe -m uvicorn src.main:app --host 0.0.0.0 --port 8080

# Linux
.venv/bin/python -m uvicorn src.main:app --host 0.0.0.0 --port 8080
```

✔ 预期：

```
INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8080 (Press CTRL+C to quit)
```

> 窗口要一直开着，关掉 = 停服。浏览器打开 **http://localhost:8080/chat**。

## 六、常见问题排查

### 1. Docker 起不来 / 端口被占用
- `docker version` 只有 Client 没有 Server → 引擎没启动，打开 Docker Desktop（或 Linux `sudo systemctl start docker`）等图标变绿。
- 端口被宿主机已有服务占用（常见：Neo4j/Redis/PostgreSQL 的 7687/6379/5432）→ `netstat -ano | findstr <端口>`（Win）或 `ss -ltn | grep <端口>`（Linux）找到占用进程停掉；或改 `docker-compose.yml` 端口映射并同步改 `.env`。

### 2. 依赖装不上
- 下载慢/超时 → 换国内镜像：
  ```sh
  pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
  ```
- Linux 报错含 `pywin32`、`win32_setctime` → 用错了文件，改用 `requirements-linux.txt`。
- 报缺 wheel/编译错误 → 确认是 Python 3.13（3.12/3.14 常缺）。

### 3. Docker 镜像拉取慢 / 失败
- 首次 `docker compose up -d` 需拉约 2-5GB 镜像，慢属正常。
- 失败重试：`docker compose pull && docker compose up -d`。
- 可给 Docker 配置 registry-mirrors 加速镜像源。

### 4. Ollama 未运行（长期记忆不可用）
- 症状：对话正常，但「保存/检索记忆」报错。
- 排查：`ollama ps` 应显示 `nomic-embed-text`；没有就 `ollama pull nomic-embed-text`，并确认 Ollama 服务在运行。

### 5. 对话报 401 / "Your api key is invalid"
- 应用读到的 Key 不是 `.env` 里的 → 系统环境变量 `DEEPSEEK_API_KEY`（旧值）覆盖了 `.env`。
- 解决：`unset DEEPSEEK_API_KEY`（Linux）/ `set DEEPSEEK_API_KEY=`（Windows）后重启应用；或把系统环境变量更新为正确 Key。

### 6. Milvus / etcd 容器起不来（数据卷异常）
- 自带数据卷可能因拷贝/中断导致状态不一致，Milvus 连接失败或 etcd 反复退出。
- 处理（会丢向量数据，其余数据不受影响）：
  ```sh
  docker compose stop milvus etcd
  # 备份后清空 etcd 与 milvus 数据
  docker exec tiangong-milvus-etcd sh -c "rm -rf /etcd/*" || true
  docker compose up -d etcd milvus
  ```
- 若彻底不行，可 `docker compose down` 后删除本地 `docker/etcd_data` 目录再 `docker compose up -d`。

### 7. 从零重建数据库（丢弃自带数据）
> 默认克隆后直接用自带数据即可，无需执行。仅当想清空重导时：
```sh
# 1. 停掉全部容器并清空数据卷（会删除自带医学数据）
docker compose down -v

# 2. 删除 .deployed 标记，让初始化脚本重新执行
del .deployed            # Windows
rm .deployed             # Linux

# 3. 重新拉起容器，等全部 healthy
docker compose up -d

# 4. 初始化数据库（仅首次，10-15 分钟）
alembic upgrade head
python scripts/init_postgres.py     # 导医学数据，约 2-3 分钟
python scripts/init_neo4j.py        # 建知识图谱，约 5-10 分钟
```

## 七、日常运维

| 操作 | Windows | Linux |
|---|---|---|
| 一键部署+启动（全新机器） | 双击 `start_dev.bat` | `./deploy/start_dev.sh` |
| 仅部署（首次一次性） | `deploy\install.bat` | `./deploy/install.sh` |
| 仅启动（日常） | `deploy\start.bat` | `./deploy/start.sh` |
| 停止应用 | 窗口 Ctrl+C | Ctrl+C 或 kill 进程 |
| 停止基础设施 | `docker compose down` | `docker compose down` |
| 升级代码 | `git pull` | `git pull` |

- 应用日志：`logs/YYYY-MM-DD.log`（项目根目录，按天滚动，保留 30 天）
- 基础设施日志：`docker compose logs -f <服务名>`
- 升级后：重装依赖（`pip install -r requirements[-linux].txt`）、有数据库变更时 `alembic upgrade head`、`docker compose pull && docker compose up -d`。
