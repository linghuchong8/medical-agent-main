# 开发上手指南（Developer Quick Start）

> 面向**第一次接触本项目的新开发者**。目标是：拿到代码 → 跑起来 → 看懂核心链路 → 能独立完成一个开发任务。
> 比 `docs/代码解释.md`（讲"是什么"）更偏**"怎么做"**：每个常见任务给出改哪个文件、怎么改、怎么验证。

## 一、总体认识（30 秒版）

一个 **FastAPI 后端 + LangGraph AI 智能体** 的医疗对话服务：

```
浏览器 /chat 页面
   │ POST /api/v1/chat
   ▼
FastAPI (src/main.py) ──► Agent (src/agents/supervisor_agent.py)
                              ├── DeepSeek 大模型（聊天/推理）
                              ├── Ollama 本地向量化（长期记忆）
                              ├── Redis 短期记忆（会话历史）
                              ├── Milvus + MinIO 长期记忆（向量库）
                              └── PostgreSQL / Neo4j（业务数据，规划中）
```

**开发时你 90% 的时间只会碰 3 个文件**：
| 文件 | 作用 |
|---|---|
| `src/agents/supervisor_agent.py` | 智能体的"大脑"：系统提示词、工具注册、聊天入口 |
| `src/agents/store_tools.py` | 给智能体的工具（新增工具在这里写） |
| `src/modules/chat.py` | HTTP 接口 + 聊天页面 |

## 三、第一次跑通（5 分钟）

1. **依赖**：本项目自带 `.venv`。若换新机器，先执行：
   ```powershell
   python -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
2. **配置**：确认 `.env` 存在（从 `.env.example` 复制），至少填 `DEEPSEEK_API_KEY`。
3. **启动基础设施容器**（7 个，含数据卷，几分钟内 healthy）：
   ```powershell
   docker compose up -d
   docker compose ps      # 全部 Running / healthy
   ```
   > 项目已固定 compose 项目名 `tiangong-agent-main`（`docker-compose.yml` 顶部 `name:` 字段），
   > 无论脚本还是手动执行都指向同一批容器，不会撞名。
4. **启动应用**：
   ```powershell
   .venv\Scripts\python.exe -m uvicorn src.main:app --host 0.0.0.0 --port 8080
   ```
   或直接双击 `start_dev.bat`（自动做以上大部分步骤）。
5. **验证**：
   - 健康检查：`http://localhost:8080/health` → `{"status":"ok"}`
   - 依赖检查：`http://localhost:8080/health/deps` → 5 项依赖 `ok`
   - 聊天页面：`http://localhost:8080/chat`，发一句"你好，我叫张三，对樱桃过敏"

## 四、一次对话的完整链路（开发者必看）

```
用户点击发送
  │
  ▼
POST /api/v1/chat                       src/modules/chat.py:29
  │  body: {user_id, session_id, message}
  │  包一层 180s 超时；遇到"会话状态损坏"自动重置 Redis checkpoint 重试
  ▼
chat_endpoint(user_id, session_id, message)   src/agents/supervisor_agent.py:100
  │  config = {configurable: {thread_id: f"{user_id}:{session_id}"}}
  ▼
agent.ainvoke({"messages":[{role:"user", content: message}]})
  │  LangGraph 智能体（create_agent 构建）
  │  1. 从 Redis 读该 thread 的历史（短期记忆）
  │  2. 组装 messages → 调 DeepSeek
  │  3. DeepSeek 决定直接回答 or 调用工具
  │  4. 若调工具：save_memory/search_memory 执行，结果回填再让模型总结
  ▼
返回 result["messages"][-1].content  →  前端展示
```

**两个记忆的机制（重点）**：
- **短期记忆** = Redis checkpoint：同 `thread_id` 的会话，历史自动带上，不用你管。
- **长期记忆** = Milvus 向量库：模型发现重要信息时**自己决定**调 `save_memory` 存；
  需要回忆时调 `search_memory` 做语义检索（Ollama 本地向量化，768 维，COSINE 检索）。

## 五、核心开发任务实操

> 每次改完代码，**必须重启 uvicorn 才生效**（服务未开 `--reload`）。
> 开发期建议用 `--reload`：改代码自动重启，省心。

### 5.1 修改系统提示词 / 角色设定

改 `src/agents/supervisor_agent.py` 的 `system_prompt`（第 71-75 行）：

```python
system_prompt=(
    "你是医疗智能助手，向用户打招呼时自我介绍为：您好！我是医疗智能助手，很高兴为您服务。"
    "当用户提到重要的个人信息或病史时，使用 save_memory 工具记住它。"
    "当需要回忆用户历史信息时，使用 search_memory 工具检索。"
    # 👉 想改人设、加规则、规定话术，都写在这里
),
```

验证：重启后到 `/chat` 问一句"你是谁"，观察是否按新设定回答。

### 5.2 新增一个工具（完整示例：回答"现在几点"）

工具定义在 `src/agents/store_tools.py`，注册在 `src/agents/supervisor_agent.py` 的 `tools` 列表。

**第 1 步**：在 `store_tools.py` 里仿照已有工具新增（注意 `@tool` + `runtime` 参数）：

```python
from datetime import datetime

@tool
async def get_current_time(runtime: ToolRuntime) -> str:
    """
    获取当前的日期和时间。
    当用户问现在几点、今天是几号/星期几等问题时调用。

    Args:
        无参数
    """
    now = datetime.now().strftime("%Y年%m月%d日 %H:%M:%S %A")
    return f"当前时间：{now}"
```

**第 2 步**：在 `supervisor_agent.py:65` 把工具加进列表：

```python
from src.agents.store_tools import save_memory, search_memory, get_current_time

tools = [save_memory, search_memory, get_current_time]
```

**第 3 步**：重启后到 `/chat` 问"现在几点"，模型会自动调用该工具拿真实时间。

> 工具三要素（模板）：
> 1. `@tool` 装饰器；
> 2. docstring 第一行写"何时调用"，参数写清含义——模型靠它决定要不要调；
> 3. `runtime` 参数可拿到 `thread_id`（见 `store_tools.py` 里的 `get_user_id`）区分用户。

### 5.3 新增 / 修改 API 接口

所有接口都在 `src/modules/chat.py` 里，两种路由器：
- `router = APIRouter(prefix="/api/v1")` → JSON 接口
- `page_router` → 页面接口（如 `GET /chat`）

仿照现有 `chat` 接口写即可：

```python
@router.get("/chat/history", response_model=...)
async def chat_history(user_id: str, session_id: str):
    ...
```

新路由要在 `src/main.py:88-89` 注册：`app.include_router(router)`。

**接口文档**：启动后访问 `http://localhost:8080/docs`（Swagger）看所有接口。

### 5.4 新增数据库表（alembic）

1. 在 `src/modules/` 下定义 SQLAlchemy 模型（仿照 `src/core/base_model.py` 的基类）。
2. 生成迁移文件：
   ```powershell
   .venv\Scripts\python.exe -m alembic revision --autogenerate -m "add_xxx_table"
   ```
   迁移文件会写到 `alembic/versions/`。
3. 应用迁移：
   ```powershell
   .venv\Scripts\python.exe -m alembic upgrade head
   ```
4. 验证：`docker exec -it tiangong-postgres psql -U medical -d medical_db -c "\dt"`

> 当前已有 2 个迁移：`147c08d69b76_init_medical_schema`、`b3469536e763_init_schema`。

### 5.5 修改聊天页面

页面是**内嵌 HTML 字符串** `_CHAT_HTML`（`src/modules/chat.py:74` 起），改样式/文案/交互都在这。
改动大时建议抽成 `src/static/` 下的独立 HTML 文件（用 `FileResponse` 返回），更好维护。

### 5.6 新增配置项（.env）

1. `.env` 里加一行：`MY_CONFIG=xxx`
2. `src/core/config.py` 的 `Settings` 类加字段：`MY_CONFIG: str = ""`（大小写自动对应）
3. 代码里 `from src.core.config import get_settings` 后 `get_settings().MY_CONFIG` 读取。

> ⚠️ 密钥只放 `.env`（已被 git 忽略），**绝不写进代码或提交**。
> `.env.example` 是模板，放非敏感默认值即可，且**不要删除**（新部署靠它生成 `.env`）。

**智能体工具是否被调用**：工具里已有 `print("🔧执行：...")`，看应用控制台输出即可确认。

**常见报错速查**：
- `对话失败: tool_calls...tool messages` → Redis checkpoint 状态损坏，接口会自动重置重试；反复出现就清 Redis。
- `embedding 失败` → Ollama 没启动或没拉 `nomic-embed-text`。
- `401 invalid token` → `DEEPSEEK_API_KEY` 不对，或被残留环境变量覆盖（用 start 脚本启动会自动清除）。
- 容器 `Conflict. name already in use` → 见 `docs/操作文档.md` 7.4。

## 十、新手常踩的坑

1. **Python 版本不对**：项目必须 3.13，装了 3.12/3.14 会装不上依赖。
2. **改了代码不生效**：没重启进程（见第八节，尤其 agent 单例）。
3. **对话一直 401/超时**：`.env` 的 `DEEPSEEK_API_KEY` 没填或填错；或环境变量里有残留旧 key。
4. **记忆功能失效**：Ollama 没启动。启动后 `ollama pull nomic-embed-text` 拉一次模型。
5. **容器起不来/撞名**：先 `docker compose ps` 看状态；撞名看 `docs/操作文档.md` 7.4。
6. **想删干净数据重来**：`docker compose down -v`（⚠️ 会清掉所有容器数据卷，慎用）。
7. **别把密钥/API Key 提交进 git**：只放 `.env`。
8. **日志在哪**：`logs/` 按天输出，排查 500 先看它。
